## 哪些限制由代码执行

已有代码核对模型、协议、有效授权、Session/Task、累计调用/步骤/Token/费用预算，
请求前预留并发余量，显式限制输出，禁用自动重试和所有执行工具。
撤销、过期、会话结束或异常会阻止新请求；已发送但结果未知时保留保守费用占用，
不会当作零消费或自动重试。普通 JSON 的 approved/trusted 字段不能产生授权能力。

**目前真实网络闸门仍然关闭。**完整 Messages 的输入 Token 上界及原始用量映射仍需
工程复核；本地字符估算和你的风险接受都不能跳过这些强制闸门。
本轮只生成审计方案，没有提供可以直接执行真实试验的命令。

## 哪些风险无法绝对消除

- 模型别名、价格或服务端计数方式可能变化；文本估算不等于完整输入的最终收费 Token。
- 网络中断、取消或超时发生时，服务端可能已继续生成或计费，客户端停止不等于退款。
- 无 Usage 或不明确的缓存字段需要保守保留占用，最终费用可能暂时无法确认。
- 余额可能同时被其他进程使用，也可能有赠款、充值、过期或延迟结算；余额差值不是本次账单。
- 尚未核实任何可直接使用的 DeepSeek 账户级硬配额 API，不会虚构或自动启用此能力。

## 批准后还需要什么

先完成剩余工程复核，重新检查模型、价格和完整请求，确认本单各项明确且没有过期。
随后才由真实交互终端登记 Operator，通过私有入口为本次 Session/Task 签发短期能力。
测试控制器的签名不能代替你的正式批准。
如果另行批准余额查询，可信宿主才可在试验前后查询、脱敏保存，并把差异标记为待归属核实。
API Key 只交给已审查的宿主使用方式；不在聊天、提示词、普通配置文件或审计输出中传递。

开始后可通过可信入口撤销本会话授权，或终止宿主进程。程序会停止后续请求，
尝试取消在途请求，并保存已发生的证据和未知费用占用；这不能撤销远端已产生的消费。
重新开始必须重新核验授权与累计记录，不存在一次勾选永久批准后续所有试验的机制。
