# 独立契约与旧接口边界

本文件属于 [Master Clarify 独立包](../SKILL.md)。旧文件名只标明兼容对象，不要求访问父仓库；独立使用只需包内 [输入契约](../contracts/clarify_input.v1.schema.json) 和 [状态契约](../contracts/clarify_state.v1.schema.json)。

## 本次兼容决策

| 对象 | 保留的旧含义 | 独立模块的处理 |
|---|---|---|
| `06-intent-elicitation` / `intent_elicitation.v1` | 可选 Phase -1a 用户意象取证；只允许继续取证或 Phase -1b；后者须四层 concrete 且估计不低于 0.75 | 不修改旧规则。新状态不强迫补齐情绪/意象，不产生分数，不把本次状态强塞到旧记录。 |
| `requirement_clarity.v1` | 包含执行清晰度、`execution_contract` 与 execute/clarify/prototype 决策 | 不作为独立状态；需求充分性与执行条件分开。 |
| `master_output_contract.v1` | Master 执行侧输出，含 `executionContract`、`shouldCreateAgent` 等字段 | 不自动生成，不将 `ready_for_planning` 映射为 execute、Runtime READY 或执行许可。 |
| Master 入口、生命周期、能力与授权闸门 | 继续决定规划之后的能力、权限、预算和执行条件 | P0–P5 保持原入口及规则，本包不建立隐式运行连接。 |
| 旧验证器、案例与打包工具 | 仍验证各自旧契约或完整 Master 包 | 独立工具验证新命名空间；旧静态通过不能证明本包语义行为通过。 |

独立命名空间为 `clarify_input.v1` / `clarify_state.v1`，不是对旧 schema 添加字段。来源与确认、需求充分性、执行条件三个维度分别保留。模型可提出需求建议，但不能靠字段名或“met”自证事实。

## CR-1…CR-6 的语义映射

CR 编号作为历史设计语义追踪，不改写任何现有 schema，也不要求为简单任务输出六份空记录。

| 历史判据 | 在独立澄清中的落点 | 不得推导的结论 |
|---|---|---|
| CR-1 目标 | 目标可描述，以及其来源/由谁确认分别记录 | 目标可描述不等于用户接受模型推断。 |
| CR-2 成功标准 | 稳定标准 ID、可观察结果、验证方式和证据类型/确认主体 | 验证方式写清不等于已验证成功。 |
| CR-3 范围 | 本阶段目标、交付、非目标、硬约束和偏好 | 长期目标不能自动成为本次必做项。 |
| CR-4 影响与授权 | 记录缺口影响的是当前规划、执行还是未来；沿用有效授权的真实来源及范围 | 缺少未来写权限不必阻断当前只读规划；就绪不补发权限。 |
| CR-5 假设 | 保留推断或默认依据、错误代价与影响判断 | 用户允许基于当前信息推进，不等于认可所有假设。 |
| CR-6 真实环境验证 | 只记录已知证据、未核验条件和待检查项；真实验证交能力/执行环节 | 未核验不普遍等于意图不清，也不能为了就绪填“已满足”。 |

## 后续接入限制

P6 只有在独立行为验收达标后才可实施。现在不安装桥接、不切换默认入口、不改旧合同字段。

未来显式桥接仅转交澄清证据与需求规格，并携带稳定 ID、版本、来源、确认状态和未决假设；旧 Core、Capability Gate、Execution Contract、权限和预算检查保留原职责。不能无损表达的新字段可以作为完整补充材料交给消费者，不编造四层证据、0.75 分数、用户确认或能力状态。

独立模块未接入时无需回滚 Master；不用此 Skill 即仍走原路径。未来桥接应先用于可禁用的显式测试入口；默认切换需要明确授权，行为验收通过本身不是默认上线许可。

离线工程证据只能支持 `ENGINEERING_OFFLINE_PASS`。缺少达到约定覆盖、成对比较和独立评审的真实模型证据时使用 `BEHAVIOR_NOT_VERIFIED`，保持 `INTEGRATION_NOT_STARTED`。不以 fixture、自拟对话、模型自评或静态关键词检查替代行为验收。
